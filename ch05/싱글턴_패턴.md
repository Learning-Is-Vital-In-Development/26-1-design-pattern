# 싱글턴 패턴

객체 인스턴스가 하나만 만들고, 그 인스턴스로의 전역 접근을 제공한다.

- 다른 어떤 클래스에서도 자신의 인스턴스를 추가로 만들지 못함. 인스턴스가 필요하다면 반드시 클래스 자신을 거치도록 해야한다.
- 언제든 인스턴스가 필요하면 클래스에 요청할 수 있게 만들어 놓고 요청이 들어오면 그 하나뿐인 인스턴스를 건네주도록 만들어야 한다.

```java
public class ChocolateBoiler {
    private boolean empty;
    private boolean boiled;
    
    private static ChocolateBoiler uniqueInstance;
    private ChocolateBoiler() {
        empty = true;
        boiled = false;
    }
    
    public static ChocolateBoiler getInstance() {
        if (uniqueInstance == null) {
            uniqueInstance = new ChocolateBoiler();
        }
        return uniqueInstance;
    }
}

```

- 나의 해석

  JVM에서 싱글턴은 Method Area에 있는 static 참조가 Heap에 존재하는 단 하나의 객체를 가리키는 구조, 이를 통해 객체의 단일성 보장 + 전역 접근 + 객체 지향적 설계를 동시에 얻는 것

    - 인스턴스 : Heap에 저장

        ```java
        MyClass obj = new MyClass();
        ```

        - `new`로 생성된 모든 객체는 Heap에 올라감
        - GC 대상
        - 클래스 하나로 **여러 개 생성 가능. 메모리 사용량 상대적으로 큼**
        - 참조 변수 `obj` 자체는 Stack에 있음
    - 정적 변수 (static 변수), 클래스 : Method Area 에 저장

        ```java
        class MyClass {
            static int count = 0;
        }
        ```

        - (JVM 스펙상의 논리 개념, Java 8부터 HotSpot JVM에서는 Metaspace로 구현)
        - 클래스가 **로딩될 때 딱 한 번 생성**
        - JVM에 클래스당 하나만 존재
        - GC 대상이 아님 (클래스 언로드 전까지)
        - 어디서든 접근 가능 (접근제어자만 허용하면)
        - 프로그램 전체에서 **공유 상태**

  > Heap에 객체는 하나만 만들고, 그 객체를 가리키는 참조를 static으로 들고 있다
  >

  static 변수 (Method Area) → Heap 객체 (1개) ←   여러 Stack 프레임에서 참조

  ### 왜 싱글턴이 좋음?

    - 인스턴스가 하나임이 보장
        - `new`를 막음 (private 생성자)
        - 실수로 여러 개 생성할 위험 없음
        - 설정 관리자, 로그, DB 커넥션 풀 같은 것에 중요
    - 전역 접근 + 객체의 장점
        - static 변수만 쓰면: 상태 관리 어려움, 인터페이스 구현 불가, 테스트에서 교체 어려움
        - 싱글턴은: 객체라서 인터페이스 구현 가능, 나중에 구조 확장 가능
    - 메모리 & 리소스 절약
        - 무거운 객체를 여러 번 만들 필요 없음,
        - JVM 전체에서 공유

## 멀티스레딩 문제

멀티스레드에서 싱글턴이 깨지는 이유는 “객체 생성 과정이 원자적이지 않은데, 여러 스레드가 동시에 접근할 수 있기 때문”

- Heap에 **Singleton 객체 2개**
- static `instance`는 마지막에 들어간 객체를 가리킴

→ 싱글턴 아님

```java
instance = new Singleton();
```

1)메모리 할당 → 2)생성자 실행 → 3) instance에 참조 할당

: JVM & CPU는 성능 때문에 **순서를 바꿀 수 있음**

- Thread-A: instance에 **참조 먼저 넣음, 생성자는 아직 덜 끝남**
- Thread-B:
    - if (instance != null) // true
    - 초기화 안 된 객체를 사용

Stack은 스레드마다 분리되어 있고, Heap과 stati은 공유하니 동기화 없으면 경쟁 발생

- synchronized

    ```java
    public static synchronized Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
    ```

    - thread-safe
    - 매번 락, 성능 저하, 실무에서 쓰면 경악데스
- Double-Checked Locking

    ```java
    public class Singleton {
        private static volatile Singleton instance;
    
        public static Singleton getInstance() {
            if (instance == null) {           // 1차 체크
                synchronized (Singleton.class) {
                    if (instance == null) {   // 2차 체크
                        instance = new Singleton();
                    }
                }
            }
            return instance;
        }
    }
    ```

    - volatile : 캐시 무시 + 최신값 보장
        - 한 스레드가 쓴 값을 **다른 스레드가 즉시 볼 수 있음**
            - 쓰기 → 메인 메모리에 즉시 반영
            - 읽기 → 항상 메인 메모리에서 읽음
        - 앞뒤의 명령어 재정렬을 막음
            - 참조 할당이 생성자 실행보다 갈수 없도록 막음
        - 원자성 보장 안함
- enum 싱글턴

    ```java
    public class SingletonClient {
        public static void main(String[] args) {
            SingletonClient client = Singleton.UNIQUE_INSTANCE;
        }
    }
    
    public enum Singleton {
        UNIQUE_INSTANCE;
    }
    ```

    - 클래스 로딩 시점에 딱 한 번 생성, JVM이 **단 하나만 생성**하도록 보장
        - 클래스 로딩 과정에서 JVM이 **미리 인스턴스를 생성 (ClassLoader)**
        - 멀티스레드 상황에서도 클래스 로딩 자체가 thread-safe라 경쟁 조건 자체가 없음
        - Effective Java: enum 싱글턴을 써라
    - 지연 초기화(Lazy Loading) 불가
        - enum은 **클래스 로딩 시 바로 생성, 무거운 리소스면 낭비 가능**
    - Spring DI 안에서 관리할 객체는 enum 싱글턴 피하자, DI, 프록시, AOP에 제약이 있음

    <aside>
    💡

  enum 싱글턴은 JVM이 관리하는 객체이고, Spring Bean 싱글턴은 Spring 컨테이너가 관리하는 객체

    - Spring에서 말하는 싱글턴은 **컨테이너 당 하나**
        - Spring이 필요시점에 생성, DI로 주입하고 프록시 감싸기 가능
        - JVM 전체X, Spring ApplicationContext 하나당 1개고 생성, 주입, 생명주기를 Spring이 관리
    - enum 싱글턴
        - JVM이 클래스 로딩 시 생성, static 접근하고 spring이 관여 안함
    </aside>
