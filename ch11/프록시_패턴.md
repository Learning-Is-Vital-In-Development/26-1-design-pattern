# 프록시 패턴

대상 객체(Real Subject)에 직접 접근하는 대신, 그 객체를 대신하는 대리인(Proxy)을 거쳐서 접근하는 디자인 패턴

- 프록시 객체는 실제 객체와 **같은 인터페이스**를 구현
- 클라이언트는 내가 지금 대화하는 상대가 진짜 객체인지, 프록시인지 알 필요가 없음
- 종류
    - 가상 프록시 : 정말 필요할 때까지 객체 생성을 미룬다
        - 가상 프록시는 메모리 사용량이 많거나 생성 비용이 비싼 객체를 다룰 때 유용
        - 객체가 실제로 사용되는 시점(메서드 호출 시) 전까지는 가짜 객체로 버티다가, 꼭 필요할 때 실제 객체를 생성(Lazy Initialization)
        - ex ) 고해상도 이미지가 많은 웹 페이지에서 텍스트를 먼저 보여주고, 이미지는 스크롤이 도달할 때 로딩하는 방식

            ```kotlin
            // 1. 공통 인터페이스
            interface Image {
                void display();
            }
            
            // 2. 실제 무거운 객체 (Real Subject)
            class HighResolutionImage implements Image {
                private String fileName;
            
                public HighResolutionImage(String fileName) {
                    this.fileName = fileName;
                    loadFromDisk(); // 생성 시점에 매우 무거운 작업 수행
                }
            
                private void loadFromDisk() {
                    System.out.println("디스크에서 아주 큰 이미지 로딩 " + fileName);
                }
            
                @Override
                public void display() {
                    System.out.println("이미지 출력: " + fileName);
                }
            }
            
            // 3. 가상 프록시 (Virtual Proxy)
            class ProxyImage implements Image {
                private String fileName;
                private HighResolutionImage realImage; // 진짜 객체의 참조
            
                public ProxyImage(String fileName) {
                    this.fileName = fileName;
                }
            
                @Override
                public void display() {
                    // 실제로 출력 명령이 내려올 때만 진짜 객체를 생성함 (Lazy Loading)
                    if (realImage == null) {
                        realImage = new HighResolutionImage(fileName);
                    }
                    realImage.display();
                }
            }
            ```

    - 원격 프록시 : 다른 서버에 있는 객체를 마치 내 옆에 있는 것처럼.
        - 원격 프록시는 다른 주소 공간에 있는 객체의 로컬 대표자 역할을 하는 프록시입니다. 클라이언트가 원격 서버에 있는 객체를 마치 로컬 객체처럼 사용할 수 있게 해주는 패턴
        - 클라이언트는 로컬에 있는 프록시 메서드를 호출할 뿐이지만, 프록시는 네트워크를 통해 원격 객체의 메서드를 대신 실행하고 결과를 전달
        - ex) Google 도큐먼트에서 협업할 때 다른 사람의 편집 상태를 확인하는 과정이나, Java의 RMI, 분산 시스템의 RPC(Remote Procedure Call)
        - 예시 : Spring Cloud OpenFeign, WebClient 등이 이 패턴을 구현한 대표적인 라이브러리

        ```kotlin
        // 공통 인터페이스
          interface PaymentService {
              PaymentResult processPayment(PaymentRequest request);
              PaymentStatus getPaymentStatus(String paymentId);
          }
        
          // 원격 서비스의 실제 구현체 (서버 측)
          class RemotePaymentServiceImpl implements PaymentService {
              @Override
              public PaymentResult processPayment(PaymentRequest request) {
                  // 실제 결제 처리 로직
                  System.out.println("서버에서 결제 처리: " + request.getAmount());
                  return new PaymentResult("SUCCESS", "PAY_" + System.currentTimeMillis());
              }
        
              @Override
              public PaymentStatus getPaymentStatus(String paymentId) {
                  System.out.println("서버에서 결제 상태 조회: " + paymentId);
                  return new PaymentStatus(paymentId, "COMPLETED");
              }
          }
          
          // 원격 프록시 (클라이언트 측)
          class PaymentServiceRemoteProxy implements PaymentService {
              private final String serverUrl;
              private final RestTemplate restTemplate;
        
              public PaymentServiceRemoteProxy(String serverUrl) {
                  this.serverUrl = serverUrl;
                  this.restTemplate = new RestTemplate();
              }
        
              @Override
              public PaymentResult processPayment(PaymentRequest request) {
                  try {
                      System.out.println("원격 프록시: 결제 요청을 서버로 전송");
        
                      // HTTP 요청으로 원격 서버 호출
                      String url = serverUrl + "/api/payments/process";
                      ResponseEntity<PaymentResult> response = restTemplate.postForEntity(
                          url, request, PaymentResult.class
                      );
        
                      return response.getBody();
                  } catch (Exception e) {
                      System.err.println("원격 호출 실패: " + e.getMessage());
                      // 기본값 반환 또는 재시도 로직
                      return new PaymentResult("FAILED", "ERROR");
                  }
              }
        
              @Override
              public PaymentStatus getPaymentStatus(String paymentId) {
                  try {
                      System.out.println("원격 프록시: 결제 상태 조회 요청");
        
                      String url = serverUrl + "/api/payments/" + paymentId + "/status";
                      ResponseEntity<PaymentStatus> response = restTemplate.getForEntity(
                          url, PaymentStatus.class
                      );
        
                      return response.getBody();
                  } catch (Exception e) {
                      System.err.println("원격 호출 실패: " + e.getMessage());
                      return new PaymentStatus(paymentId, "UNKNOWN");
                  }
              }
          }
        ```

    - 동적 프록시 : 런타임에 코드가 알아서 프록시 객체를 만들어준다.
        - 컴파일 시점이 아니라 애플리케이션이 실행 중인 **런타임**에 프록시 객체를 자동으로 생성 → 일반적인 프록시 패턴은 개발자가 직접 프록시 클래스를 일일이 작성
        - 동적 프록시 패턴은 런타임에 프록시 객체를 동적으로 생성하는 디자인 패턴입니다. 일반적인 프록시 패턴과 달리, 컴파일 타임에 프록시 클래스를 미리 정의하지 않고 실행 시점에 Reflection을 사용해 프록시를 만든다
        - ex) Spring 프레임워크의 **AOP(관점 지향 프로그래밍). 데이터베이스 트랜잭션을 걸거나 실행 시간을 측정하는 로그를 남길 때 사용자가 작성한 비즈니스 로직 앞뒤에 자동으로 프록시를 붙여 실행.  @Transactional**
        - 예시 : 클래스를 직접 만들지 않고, 실행 중에(Runtime) 자바가 알아서 프록시 객체를 찍어내게 만든다

        ```kotlin
         // 1. 대상 인터페이스
          interface UserService {
              User findById(Long id);
              void save(User user);
          }
        
          // 2. 실제 구현체
          class UserServiceImpl implements UserService {
              @Override
              public User findById(Long id) {
                  System.out.println("실제 사용자 조회: " + id);
                  return new User(id, "User" + id);
              }
        
              @Override
              public void save(User user) {
                  System.out.println("실제 사용자 저장: " + user);
              }
          }
        
          // 3. InvocationHandler 구현
          class LoggingInvocationHandler implements InvocationHandler {
              private final Object target;
        
              public LoggingInvocationHandler(Object target) {
                  this.target = target;
              }
        
              @Override
              public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
                  System.out.println("메소드 호출 전: " + method.getName());
                  long start = System.currentTimeMillis();
        
                  try {
                      Object result = method.invoke(target, args);
                      return result;
                  } finally {
                      long end = System.currentTimeMillis();
                      System.out.println("메소드 호출 후: " + method.getName() +
                                        " (실행시간: " + (end - start) + "ms)");
                  }
              }
          }
        
          // 4. 동적 프록시 생성 및 사용
          public class DynamicProxyExample {
              public static void main(String[] args) {
                  // 실제 객체 생성
                  UserService realService = new UserServiceImpl();
        
                  // 동적 프록시 생성
                  UserService proxyService = (UserService) Proxy.newProxyInstance(
                      UserService.class.getClassLoader(),
                      new Class[]{UserService.class},
                      new LoggingInvocationHandler(realService)
                  );
        
                  // 프록시를 통한 메소드 호출
                  proxyService.findById(1L);
                  proxyService.save(new User(2L, "NewUser"));
              }
          }
        ```
